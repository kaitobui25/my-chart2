# 3. Bug cần sửa — bằng chứng thực tế mới nhất

Bug không phải giả thuyết. Browser thật đã reproduce nhiều lần.

Scenario:

- Workstation chạy 2 chart Binance Spot.
- Chart BTCUSDT có dữ liệu cache nên render được.
- Chuyển chart còn lại sang ETHUSDT 1M khi ETH chưa có cache.

Điều đáng chú ý: fallback timeout trong code được đặt thấp hơn các elapsed thực tế, nên **không được tin rằng timeout/fallback đang hoạt động đúng chỉ vì unit test pass**. Phải đo trên browser thật.

# 8. Giai đoạn C — Verify chính xác request path trong browser

Đây là bước bắt buộc trước khi code patch.

Khi switch ETHUSDT 1M, inspect từng request.

Bạn phải xác định:

### Primary

Nó có thực sự gọi dạng:

```text
http://127.0.0.1:53173/binance-spot-api/api/v3/klines?...
```

hay browser vẫn gọi thẳng:

```text
https://data-api.binance.vision/...
```

### Fallback

Khi log nói `api-gcp`, `api1`, `api2`, Network tab có cho thấy browser gọi thẳng các HTTPS host đó không?

Nếu đúng, ghi lại bằng chứng.

### Phân loại root cause theo ma trận

#### Case 1 — localhost proxy nhanh, direct browser Binance chậm/fail

Root cause nằm ở browser direct network path hoặc fallback architecture.

Hướng sửa hợp lý có thể là route toàn bộ fallback qua local proxy/server-side hoặc dùng một server-side failover mechanism. Nhưng phải test sau khi sửa.

#### Case 2 — direct curl nhanh, browser direct chậm/fail

Rất mạnh về browser networking/CORS/policy/throttling.

Ưu tiên loại browser direct fetch khỏi critical REST path.

#### Case 3 — cả curl direct và localhost proxy đều fail

Đây không còn là frontend race đơn thuần. Kiểm tra:

- DNS resolution
- IPv4/IPv6 behavior
- ISP/VPN/firewall
- Binance host accessibility từ Nhật / mạng hiện tại
- Node fetch vs curl

Đừng thêm retry vô hạn.

#### Case 4 — Network request trả 200 nhưng chart vẫn 0 candle

Lúc này bug ở parse/cache/stale-token/dataset coordination/render path.

Phải inspect response payload và trace từ `getHistory()` tới `Tile.load()`/chart.setCandles().

#### Case 5 — request bị AbortError trước timeout dù network host bình thường

Trace toàn bộ `AbortController` owner.

Ghi rõ controller nào gọi `.abort()` và do event nào.

Không được chỉ bắt AbortError rồi retry.

# 10. Giai đoạn E — Fix root cause

Chỉ sửa sau khi có bằng chứng.

Nguyên tắc:

- Ưu tiên một network architecture rõ ràng, deterministic.
- Foreground latest history phải có ưu tiên cao hơn background older-history.
- Hai chart độc lập không được abort nhau.
- Symbol/timeframe cũ không được render sang dataset mới.
- Cache miss phải thực sự đi remote và trả candle, không được đứng 0 vô thời hạn.
- Provider không được global-disable chỉ vì một AbortError local.
- Không được làm hỏng replay / load older / realtime / VN providers.
- Không được che lỗi bằng cache.

Nếu root cause là fallback direct browser trong khi primary dùng proxy, cân nhắc thống nhất transport. Tuy nhiên phải dựa vào probe thực tế, không tự động áp dụng chỉ vì prompt gợi ý.

Nếu cần sửa Vite proxy, nhớ:

- restart `npm run dev` sau thay đổi;
- test route localhost trực tiếp bằng curl;
- test browser Network xác nhận URL thực tế;
- thêm regression test cho mapping để tránh adapter có host nhưng Vite không có route tương ứng.

Nếu cần sửa timeout, phải có hard deadline thực tế và test elapsed wall-clock, không chỉ fake timer unit test.
